# v0.17.0 — release material (raw notes for the docs rewrite)

Scratch checklist of everything this release changes, so the Hugo docs
(`website/content/docs/...`) and the GitHub release notes can be written from one
source. **v0.17.0 is a breaking release.** Not user-facing prose — organize/polish
at release time.

## New features

- **External (sidecar) IPAM.** A ServiceGroup can now request addresses from an
  external IPAM system reached over a gRPC sidecar in the allocator pod.
  - `ServiceGroup.spec.external{ provider, socket, announce }` (provider = cosmetic
    name shown in `.status.ipam`; socket = sidecar's Unix socket; announce =
    `local`|`remote`).
  - gRPC contract `api/ipam/v1/ipam.proto` — 3 RPCs: `Allocate` / `Release` / `Stats`.
  - `.status.ipam` + address counts reflect the sidecar's `Stats`.
  - Sample/reference sidecar: `cmd/test-sidecar` (in-memory). **Its image must be
    built + pushed for the e2e / for users to try it** (`test-sidecar` not yet in GHCR).
  - This is the supported replacement for the removed in-tree Netbox.

- **Multi-pool & balanced allocation** (`spec.local` and `spec.remote`):
  - `v4pools[]` / `v6pools[]` — multiple ranges per family (each with `subnet`,
    `pool`, `aggregation`).
  - `multiPool: true` — a service gets **one IP from each pool**, i.e. a VIP on
    every subnet (reachable from all subnets). Dual-stack → one v4 + one v6 per pool.
  - `balancePools: true` — new allocations pick the least-used range (even spread);
    **mutually exclusive with `multiPool`**.

- **IP-keyed `purelb.io/announcing-*` annotations.** Each announced IP is now its
  own slot; the election winner owns and overwrites it, losers don't write. Fixes
  stale/duplicate accumulation from the old append-only behavior and correctly
  represents multi-pool (one entry per IP).
  - Format per entry: `node,interface,ip`, entries space-separated. **Correct the
    docs' old 2-field `node,interface` format everywhere.**
  - New metric: `purelb_lbnodeagent_announce_slot_steal_total{from,to}` — fires when
    a node overwrites a slot another node claimed (split-brain / migration signal).

## Removed / breaking

- **In-tree Netbox removed** (`spec.netbox` gone; CEL-rejected). Migrate to a
  sidecar via `spec.external`.
- **v2 API** is the served/stored version (see `docs/migration-v1-to-v2.md`).
- Add a v0.17.0 entry to the migration guide covering Netbox → sidecar and the
  annotation-format change.

## Fixes worth a release-note line

- Shared IPs now withdraw correctly on election loss (refcount actual announced
  state, not `svcIngresses`) — fixes an address stuck on the old node.
- Write-amplification: informer Service is DeepCopied before mutation; peers'
  announcing-only writes no longer re-enqueue every node; 10-min resync floor.
- GARP gated to IPv4 (was erroring on IPv6 announces) and an ARP socket fd leak in
  `sendGARP` closed.
- `kubectl-purelb` no longer counts a departed node's stale annotation slots as
  announcing (lease-gated).

## Known limitations / operational notes to document

- **shared-IP + `node-affinity` are mutually exclusive.** If both are set, sharing
  wins and affinity is **silently ignored** (VIP does not follow endpoints). Verified
  benign (VIP stable, reachable). Consider documenting; a warning event is a possible
  future nicety.
- External-pool `.status` counters can go **stale** until the next event
  (`SidecarPool.Contains` returns false); data plane is unaffected.
- `purelb.io/re-evaluate` does **not** re-allocate an IP after its pool/subnet
  changes (keeps the now-orphaned IP). Workaround: delete + recreate, or pin a new
  address. (Bug, fix later.)
- **IPv6 neighbour convergence after a VIP migration:** a neighbour can hold the old
  MAC for up to ~53s. Recommend `net.ipv6.conf.all.ndisc_notify=1`. There is **no
  unsolicited-NA sender yet** (the IPv6 counterpart to GARP) — note as a known gap.
- Issue #60 display gap: a ServiceGroup with no allocations shows blank `.status`
  (and blank `kubectl get sg` columns) until first use.
